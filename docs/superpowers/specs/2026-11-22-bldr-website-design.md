# BLDR website: design

Date: 22 November 2026. Status: approved by Otto on 22 November 2026.

## Why

BLDR's own home page, for people Otto wants to show the app to (mostly friends). It will be linked from Otto's future portfolio site, next to Pantry Mate. It sits in its own folder and GitHub project, so anyone who copies the app's code doesn't get the website with it.

The approved look and wording are the mockup at https://claude.ai/artifact/FtnbvSCk13iSDCAFXNqWr1 (version 9). That mockup is the reference for everything below.

## Goals

- Four pages: Home, Features, Get BLDR (download and install steps), FAQ.
- BLDR's black-and-white brand: the striped B, Archivo Expanded Black for headings, Space Grotesk for text.
- Pantry Mate's story-scroll layout: a hero, a pinned phone that changes screens across four steps, a library section, "Before you install" cards, and a closing band. It includes the scroll effects from the mockup.
- Lead with the AI Coach and the exercise library. Present BLDR as open source and "bring your own Claude key".
- A visible link to the GitHub project:
  - the "Source code" link at the bottom of every page
  - the "BLDR on GitHub" button and "Older versions" link on Get BLDR
  - a link in the home page's "Open source" card
  - a link in the FAQ answer "Can I change the app?"

## Not doing

- No sign-ups, accounts, forms, blog or visitor tracking.
- No Play Store listing.
- No link back to the portfolio yet. It can be added once the portfolio exists.

## Must avoid

- Any story about who built BLDR or why.
- Marketing hype, or wording that sounds machine-written:
  - slogans
  - question headlines
  - lists of three fragments
  - "not X but Y"
  - dashes used as asides
- Any claim the app doesn't back up. The app's code and its GitHub release notes are the source of truth.

## Approaches

| | What it is | Trade-off |
|---|---|---|
| **A. Plain static site (chosen)** | Plain HTML pages with one shared stylesheet and one small script. No add-ons and no build step. | Matches the mockup exactly, has very little that can break, and loads fast. Anything interactive later (a form, say) has to be added by hand. |
| B. React, like Pantry Mate | The same pages built with React and Vite. | Matches Otto's other sites, but adds dozens of add-ons and a build step for four pages of text. The scroll effects come out the same either way. |
| C. Inside the portfolio site | The pages become part of the portfolio project. | The portfolio work is paused, and each app is meant to have its own home page. |

Otto chose A on 22 November 2026.

## How it's built

**Files:**

```
bldr-home-page/
  index.html        Home
  features.html     Features
  get.html          Get BLDR
  faq.html          FAQ
  404.html          "Page not found", with a link home
  styles.css        shared styles (from the mockup)
  site.js           shared scroll effects; each part runs only if its section is on the page
  vercel.json       serves pages without ".html" (/features, /get, /faq)
  assets/           promo.mp4, promo-poster.jpg, fonts, favicon, share image
  README.md         what this is and how to update it
```

**Changes from the mockup:**

- Each view becomes its own page with a real web address. The mockup's single-page switching is removed.
- The mockup notes (the dashed boxes) and the floating page switcher are removed. The page no longer needs the extra space at the bottom that the switcher took.
- The Features content is written straight into the page, instead of being generated by the script. It then shows up without the script and for search engines.

**Additions:**

- **Tab icon:** the striped B.
- **Page details:** a title and description on each page.
- **Share preview:** an image for when the link is pasted into a chat. A 1200×630 picture: the B mark and the headline on black.

**Behaviour that carries over from the mockup:**

- The promo video plays only while it's on screen.
- With "reduce motion" turned on, everything stays still.
- The pages work at phone width with no sideways scrolling.

**Things to update on each app release:**

- The version number appears as text in three places: the download card, the footer, and the FAQ's "What's new" list.
- The download button always fetches the newest file from GitHub, so it never needs changing.

## Hosting

- **Online copy:** a new public GitHub project, `otto-tries-to-build-stuff/bldr-home-page`, like the app's.
- **Hosting:** Vercel, as the project `getbldr`, deployed with the Vercel tool that is already signed in on Otto's computer. The project is connected to the GitHub project, so every upload to `main` republishes the site automatically.
- **Web address:** `getbldr.vercel.app`. Otto asked for `bldr.vercel.app`, but someone else already has it, as do `bldr-app` and `bldrapp`. A custom domain can be added later.

## Checking it works

- Screenshots of all four pages, at phone width (390 px) and desktop width (1280 px).
- No browser errors.
- Every link opens. The APK link goes to the newest release.
- The scroll effects run, and everything stays still with reduce motion turned on.
- The pages are still readable with the script turned off.

- The exact layout of the share image.
- Small spacing fixes that turn up while checking the screenshots.
